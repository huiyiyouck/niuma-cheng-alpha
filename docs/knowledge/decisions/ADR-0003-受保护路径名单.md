# ADR-0003: 受保护路径名单

- 日期: 2026-08-15
- 状态: 提议（待 v0.1 设计文档 Review 通过后转「已采纳」）
- 关联: `docs/baseline/conventions.md` §受保护路径删除 Review 门禁；`docs/baseline/project-context.md` §受保护路径

## 背景

`runtime.md` [P0] 规定：受保护路径（业务源码 / 部署配置 / baseline / 模板 / 入口文件）的删除必须走架构师 Review 门禁，且名单**由 ADR 明确**。`project-context.md` 目前只写了「缺省最小集」并注明待 Architect 在 ADR 中回填。v0.1 设计确定了业务源码的物理位置与运行产物目录，具备了定名单的条件。

定名单要回答的是一个具体问题：**哪些文件误删会造成不可重算的损失。** 不是「哪些文件重要」——重要但可重算的东西不需要门禁，加进名单只会稀释门禁的严肃性。

## 决策

### 受保护路径（删除须走架构师 Review 门禁）

| 路径 | 类别 | 不可重算的原因 |
|------|------|----------------|
| `alpha_platform/**` | 业务源码 | v0.1 全部实现 |
| `.brain_credentials` | 凭据 | Owner 手工维护，删除即失去平台访问；且不入库、无副本 |
| `data/snapshots/**` | 提交证据 | ★ 提交是不可逆动作，快照是唯一的事后追溯证据，**不可由库文件重算** |
| `docs/baseline/**`、`docs/templates/**` | 工作流框架 | 框架真源的下游副本，删除破坏工作流 |
| `CLAUDE.md`、`AGENTS.md` | 助手入口文件 | 同上 |
| `docs/research/**` | 调研快照与事实 | 立项调研原始材料（Demo 快照）与 API 实测事实，重新获取成本高、部分不可复现 |
| `docs/progress/**` | 进度真源 | 迭代记录、PRD、设计文档、角色日志——项目级决策留痕 |

### 明确**不**受保护

| 路径 | 为什么 |
|------|--------|
| `data/inventory.db` | 可重算：删除后 `sync --full` + `classify` 即恢复。这正是 ADR-0001 字段分层与 PRD M4「备份 = 复制库文件、恢复 = 重算」要达到的效果 |
| `data/`（除 `snapshots/`） | 同上；断点状态（`sync_slice`）是临时派生数据，删除最多导致重跑 |
| `__pycache__/`、`.venv/` | 构建产物 |

`data/snapshots/` 是 `data/` 目录中唯一的例外——**它是证据，不是产物**。

## 考虑的替代方案

| 方案 | 优点 | 缺点 | 为什么不选 |
|------|------|------|------------|
| 保护整个 `data/` | 名单简单 | 库文件是最常需要删除重建的东西（改 schema、重来一遍），每次都走 Review 门禁会让门禁变成橡皮图章 | 门禁的价值在于稀缺；保护可重算的东西会稀释它 |
| 只保护缺省最小集，不列 `data/snapshots/` | 与现有 project-context 一致 | 提交快照恰恰是全项目唯一「不可逆动作 + 不可重算」的交集 | 遗漏它等于让唯一真正需要保护的新增产物落在门外 |
| 不保护 `docs/research/` | 它只是参考材料 | Demo 快照对应的 pip 包仍在活跃演进（v4.1.4 构建于 2026-08-11），当时的快照无法精确复现；API 实测事实需要真实账号才能重新获取 | 重新获取成本高且部分不可复现，符合「不可重算」判据 |

## 后果

**正面**

- 名单判据统一为「不可重算」，可解释、可扩展；后续新增路径时有明确的纳入标准。
- `data/inventory.db` 明确排除，使「删库重来」成为无摩擦的常规操作，与 M4 的设计意图一致。
- `data/snapshots/` 纳入保护，补上了 PRD 定稿后新增产物的治理空白。

**负面**

- 名单比 `project-context.md` 现有的缺省最小集长，需要同步回填该文件（实现阶段随首个 commit 一并处理）。

**风险**

- 门禁只约束 Agent 行为，不阻止 Owner 手工删除。`data/snapshots/` 若需长期保全，应由 Owner 自行做异地备份——本 ADR 不承诺技术强制。
