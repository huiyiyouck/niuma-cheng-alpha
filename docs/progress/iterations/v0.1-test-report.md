## 需 Review 方裁定的偏离（1 处）

设计 §3.1.1 写「每个公开方法进入时先 `_ensure_authenticated()`：检查 cookie → **GET `/authentication` 探活** → 失效则重认证」。

实现改为：**首次认证 + 业务请求遇 401 时自动重认证并重试一次**（`client.py::_ensure_authenticated` / `_request_json`）。

- 理由：按字面每次探活，会让全量同步的请求数**翻倍**（1 万条按 page_size=100 约 100+ 次业务请求 → 再加 100+ 次探活）；而 §3.1.1 自陈的目标是「无需实测 session 生命周期，**按需**重认证即可覆盖长任务中途失效」——401 触发正是「按需」，目标完全达成。
- 覆盖：`test_client.py::test_业务请求遇_401_自动重认证并重试一次` 断言认证被调用两次（首次 + 401 后）。
- 若 Architect 认为应严格照字面实现，改动量很小（在 `_ensure_authenticated` 内加一次探活请求），请在 Review 中明示。

- **正常路径**：全量同步（切片 → 穷尽 → 对账）、增量同步、分流三分类、两阶段预判三态、报告四块、dry-run → confirm → 快照落盘、reconcile 收敛；CLI 五条命令串联跑通。
- **边界值**：时间轴首末条与同一秒多条（D9）；同一秒挤满记录导致无法细分（D11，落 `partial`）；`limit == 0` 与 `value/limit` 缺省的不可量化 FAIL；空清单指纹；`--limit` 截断；offset 封顶（切片能拉全、直连撞上限）。
- **异常路径**：认证失败 / 生物识别分支 / 凭据文件缺失与格式错；429 退避后成功与重试耗尽；5xx；相关性重试耗尽返回 `None`；预判中途抛异常（已完成部分不丢）；提交中途进程死亡（留 `in_flight`）；快照写盘失败（不进提交循环）；reconcile 查询失败（保持不动）。
- **状态转换**：已回测 → 三类候选；可提交候选 → 待确认 / 改造候选 / 待定标注；待确认 → 已提交 / 提交失败；`in_flight` → 已提交 / 退回待确认；保护态在分流与预判中均不被改写；同步再次执行时派生字段保持不变。
