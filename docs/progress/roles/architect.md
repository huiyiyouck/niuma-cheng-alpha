## 2026-08-15 — 会话摘要（设计阶段 R1 产出）
- 本次角色：Architect（架构师）
- 动作：产出
- 涉及文档：`iterations/v0.1-design.md`（新建，R1 送审）、`knowledge/decisions/ADR-0001~0004`（新建）、`knowledge/INDEX.md`（ADR 登记）、`iterations/v0.1.md`（设计阶段门禁 R1 行）、`docs/progress/INDEX.md`
- 结论：设计 R1 送审，指定 Developer + DevOps 两方 Review。
- 关键取舍（选了什么 / 备选什么 / 为什么）：
  - **窗口级对账**（ADR-0002）：PRD #1 主口径若按字面实现（本地条数 vs 切片求和），因切片是唯一写入路径而两数恒等——会退化回 R1-A4 的自证循环。把断言下沉到「每个叶子窗口实际拉取数 == 平台报告 count」才可证伪。这是本次设计里最关键的一处「照字面实现会错」。
  - **窗口边界重叠 1 秒**：平台 `dateCreated>` / `dateCreated<` 两端都是开区间，首尾相接会让边界记录被两侧同时排除而**静默丢失**；重叠 + 主键去重，与 PRD「去重条数」口径天然契合。
  - **预判两阶段短路**（ADR-0004）：依据 Demo skill 记载的「self-corr > 0.7 则 prod-corr 必然 > 0.7」，self 超阈即判死不查 prod，最坏调用次数减半；误判方向保守（不会造成误提交），且 `short_circuited` 留痕可批量复查。
  - **只存 raw_json 不逐字段建列**（ADR-0001）：拆列会让同一数据两处存储，与「平台原始不可变、单一真源」冲突；1 万条 JSON 解析在手动命令下是秒级，不值得用一致性风险换查询便利。
  - **原始/派生分两张表**：让「同步不触碰派生」由 schema 物理保证，而不是靠实现者的代码纪律——PRD §3.1 是硬约束，值得用结构兜。
  - **预判断点不建表**：「已有结论就跳过」与「断点续跑」是同一件事，复用 `prediction_result` 非空即可，两个状态载体必然漂移。
  - **不选本地 PnL 快算**：PRD #6 定稿口径写明走 self/prod 接口；本地快算引入新数据面，且本地相关性算法需自行验证与平台口径一致。已留 `CorrelationResult` 边界，v0.2 换实现不动上层。
  - **受保护路径判据定为「不可重算」**（ADR-0003）：`data/snapshots/` 纳入（提交证据，不可由库重算）、`data/inventory.db` 排除（删了重跑即可）。保护可重算的东西会把门禁变成橡皮图章。
