### 二、核心模型：漏斗 + 改造回路

**平台规则（BRAIN 侧）**：回测得到平台评分 → 评分达标才有提交资格 → 提交即有收益（收益由平台自动产生）。

**产品核心模型**：

```text
组装 → 待回测 → 回测 → 得到平台评分
                          │
          ┌───────────────┼────────────────┐
          │               │                │
     未达标但有潜力    达标但平庸      达标且优秀
          │               │                │
          └──→ 改造 ──→ 再回测（循环）      提交 → 收益
                                          （评分越高越好）
          改造若干轮仍无起色 → 淘汰（退出漏斗）
```

**关键产品洞察（Owner 原话提炼）**：BRAIN 平台管的是「已进入平台的 Alpha」；Owner 真正的资产是**本地组装的 Alpha 库存**。例：本地组装 1 万个、只回测 5000 个，需要一眼看到每个 Alpha 处在漏斗哪一级、为什么卡住、下一步推谁。管理面 = **组装漏斗的状态管理**，不是已提交成品的仪表盘。

**改造策略（两类都进改造回路）**：
1. 未达标但回测结果较好 → 改造 → 再回测 → 达标后提交；
2. 已达标但评分平庸 → 改造 → 更优 → 再提交。

### 三、产品设计推论（Owner 已认同）

1. **AI 智能双核心**：组装核心（假设 → 数据 → 表达式的生成）+ 改造核心（按评分判断怎么改）。批量回测是体力活，两个智能核心是本平台与「无脑批量跑」工具的本质区别。
2. **谱系管理**：改造回路产生父 → 子 → 孙版本链，管理面须可见「一族改了几轮、评分变化、哪个版本最终提交」。
3. **淘汰终态**：无潜力 / 改造多轮无起色的 Alpha 须可标记淘汰退出漏斗；淘汰规则（轮数上限、评分下限）是重要产品参数。

### 四、范围边界

- 本产品做：Alpha 组装、批量回测调度、评分分流、改造回路、提交、组装漏斗管理（含谱系）、Web 可视化。
- 本产品不做：收益追踪/统计（提交即有收益，属 BRAIN 平台自身机制）；对外分发（纯自用）；接入外部 Agent Hub（预留接口，暂不实现）。

### 五、平台调研发现（2026-08-13，API 实测）

事实全文见 `docs/research/brain-platform-facts.md`，对定位的关键支撑：

1. **评分体系 = 机器可读 checks 清单**（name/result/limit/value，result ∈ PASS/FAIL/WARNING/ERROR/PENDING）→ 评分分流可 100% 程序化，改造方向判断有结构化输入（FAIL 项即「病历」）。
2. **检查分两梯队**：回测即出的硬门槛（Sharpe≥1.58、Fitness≥1.0 等，随 region/universe 变化）+ 提交前按需计算的相关性/多样性检查（PENDING 类）→ 漏斗「已回测 → 可提交判定」须拆两步。
3. **账号实测库存**：未提交 10000（或为计数上限）vs 已提交 88 → 印证「组装快、推进慢」，本地漏斗库存管理是真痛点。
4. **列表 API 单页自带全量指标 + checks + 代码** → 本地库存库分页同步可行，技术上无障碍。
5. **组装搜索空间机器可读**：19 项仿真设置全集（OPTIONS /simulations）+ 102 操作符 + 数据字段 API。
